# 서버 이미지 저장 및 관리자 인증 구현 계획

> 승인된 설계: `docs/plans/2026-09-13-server-image-storage-design.md`

## 1. 서버 저장 기반 구성

- `.openai/hosting.json`에 `DB`, `BUCKET` 논리 바인딩을 선언한다.
- D1 스키마와 최초 마이그레이션을 추가한다.
- 서버 환경 형식, 응답 유틸리티, 해시·난수 도우미를 분리한다.
- 마이그레이션과 바인딩 구성이 빌드 결과에 포함되는지 검증한다.

## 2. Google 관리자 인증

- 실패하는 인증 단위 테스트부터 작성한다.
- OAuth 시작, 콜백, 토큰 검증, 1회성 state 소비를 구현한다.
- 지정 관리자 이메일의 최초 `sub` 바인딩과 충돌 거부를 구현한다.
- 해시 세션 저장, 만료 확인, 로그아웃, 동일 출처 검증을 구현한다.
- 비관리자·만료·재사용·nonce 불일치 테스트를 통과시킨다.

## 3. 이미지 API

- 공개 메타데이터 및 이미지 조회 테스트를 작성한다.
- 관리자 업로드·교체·삭제 권한 테스트를 작성한다.
- 원본·썸네일 R2 저장과 D1 활성 버전 교체를 구현한다.
- 캐시 헤더, 파일 형식·용량 검사, 부분 실패 정리를 구현한다.
- 삭제 후 번들 이미지 대체와 이전 객체 보존을 검증한다.

## 4. 화면 연동

- 이미지 API 클라이언트와 전역 공개 이미지 맵 공급자를 추가한다.
- `SampleCard`가 서버 썸네일을 우선 표시하도록 테스트 후 변경한다.
- 상세 페이지가 서버 원본을 우선 표시하도록 테스트 후 변경한다.
- 관리자 로그인 상태에 따라 업로드·교체·삭제 UI와 드래그앤드롭을 제한한다.
- 로그인·로그아웃·업로드 진행·오류·성공 상태를 기존 UI 스타일에 맞춰 표시한다.

## 5. 검증과 공개 배포

- 전체 단위 테스트, 타입 검사, 프로덕션 빌드를 실행한다.
- 로컬 D1 마이그레이션과 Worker API를 검증한다.
- Google OAuth 환경값을 신규 사이트에 설정한다.
- 신규 버전을 배포하고 사이트 공개 범위를 `모든 방문자`로 설정한다.
- 실제 관리자 로그인과 이미지 업로드·목록·상세·제품계열·유사색상 표시를 확인한다.
- 문제가 있으면 기존 GitHub Pages를 유지하고 신규 사이트만 수정한다.

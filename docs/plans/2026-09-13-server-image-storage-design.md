# 서버 이미지 저장 및 관리자 인증 설계

## 목표

제품 이미지를 브라우저별 `localStorage`가 아니라 서버에 보관한다. 등록된 이미지는 모든 방문자가 로그인 없이 볼 수 있고, 업로드·교체·삭제는 지정된 관리자 Google 계정만 수행할 수 있게 한다.

## 운영 구조

- 신규 공개 사이트 한 곳에서 정적 화면과 `/api/*` 서버 기능을 함께 제공한다.
- R2 `BUCKET`에는 원본과 400px 목록용 썸네일을 버전별 객체로 저장한다.
- D1 `DB`에는 사용자, OAuth 시도, 세션, 제품 이미지 메타데이터, 감사 기록을 저장한다.
- 기존 GitHub Pages 배포는 새 사이트 검증이 끝날 때까지 유지한다.
- 신규 사이트 예정 주소는 `https://ebook-sample-book-live.swoony-crown-0716.chatgpt.site`이다.

## 인증과 권한

- Google OAuth 2.0 Authorization Code + PKCE 흐름을 사용한다.
- 로그인 시작 시 서버가 `state`, `nonce`, PKCE verifier를 생성하고 D1에 해시 형태로 짧게 보관한다.
- 콜백에서 Google 서명, issuer, audience, 만료, nonce, `email_verified`를 검증한다.
- 지정 이메일 `tubebluemoon@gmail.com`만 최초 관리자 계정으로 바인딩할 수 있다. 최초 바인딩 뒤에는 Google의 불변 `sub`를 기본 식별자로 사용한다.
- 세션 토큰은 난수로 생성하고 D1에는 해시만 저장한다. 쿠키는 `HttpOnly`, `Secure`, `SameSite=Lax`로 설정한다.
- 세션은 최대 12시간, 미사용 2시간으로 제한하며, 이미지 변경 API는 요청마다 현재 사용자 상태와 관리자 역할을 다시 확인한다.
- 업로드와 삭제 요청은 동일 출처인지 검증한다. 화면에서 버튼을 숨기는 것과 별개로 서버가 최종 권한을 판정한다.

## 이미지 흐름

1. 상세 페이지는 공개 메타데이터 API에서 해당 제품의 서버 이미지 존재 여부와 버전을 조회한다.
2. 서버 이미지가 있으면 상세·목록·제품계열·유사색상에 동일한 공개 이미지 URL을 사용한다.
3. 서버 이미지가 없으면 기존 번들 이미지로 대체한다.
4. 관리자가 파일을 선택하면 브라우저에서 400px 썸네일을 생성하고 원본과 함께 멀티파트로 전송한다.
5. 서버는 이미지 형식, 파일 크기, 제품 ID, 인증 상태를 검증한 뒤 새 버전을 R2에 기록하고 D1 메타데이터를 교체한다.
6. 교체 전 객체는 30일 복구용으로 남기며, 삭제도 D1에서 소프트 삭제로 기록한다.

## API

- `GET /api/auth/me`: 현재 관리자 로그인 상태 조회
- `GET /api/auth/google/start`: Google 로그인 시작
- `GET /api/auth/google/callback`: Google 콜백 처리
- `POST /api/auth/logout`: 세션 폐기
- `GET /api/product-images`: 현재 공개 이미지 버전 맵 조회
- `GET /api/product-images/:productId/:variant`: 원본 또는 썸네일 공개 조회
- `POST /api/product-images/:productId`: 관리자 전용 업로드·교체
- `DELETE /api/product-images/:productId`: 관리자 전용 소프트 삭제

## 데이터 모델

- `users`: Google `sub`, 검증 이메일, 역할, 상태, 생성·수정 시각
- `oauth_attempts`: 해시된 state, nonce, PKCE verifier, 브라우저 바인딩, 만료·소비 시각
- `sessions`: 토큰 해시, 사용자 ID, 절대·유휴 만료, 마지막 사용 시각
- `product_images`: 제품 ID, 활성 버전, 원본·썸네일 객체 키, MIME, 크기, 수정자, 삭제 시각
- `audit_events`: 로그인, 업로드, 교체, 삭제 결과와 대상 제품, 실행 사용자, 시각

## 오류와 복구

- 인증되지 않은 변경은 `401`, 권한 없는 계정은 `403`, 형식·용량 오류는 `400/413`으로 구분한다.
- 업로드가 실패하면 기존 활성 이미지는 바꾸지 않는다.
- D1 반영 전에 R2 저장이 일부 성공하면 새 객체를 정리하고 기존 메타데이터를 유지한다.
- 읽기 장애 시 제품 화면은 기존 번들 이미지로 대체하고, 관리자에게만 재시도 안내를 표시한다.
- 감사 기록과 30일 보관 객체를 이용해 운영 중 실수 삭제를 추적·복구할 수 있게 한다.

## 배포 전 필수 조건

- Google OAuth 웹 클라이언트 ID·시크릿과 정확한 콜백 URL 등록
- D1 마이그레이션의 로컬 호환성 확인
- 비로그인 변경 거부, 관리자 실제 로그인, 업로드·교체·삭제·로그아웃 검증
- 신규 사이트를 공개로 설정하되 변경 API는 계속 관리자 전용으로 유지
